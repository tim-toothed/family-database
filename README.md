# Семейное древо

Статический сайт для просмотра семейной базы данных. Проект показывает родственные связи в виде графа, таблицы и карточки выбранного человека. Данные хранятся в YAML-файлах и могут публиковаться на GitHub Pages без отдельного backend.

## Что умеет сайт

- строить интерактивный граф родственных связей;
- переключаться между графом и таблицей людей;
- показывать подробную карточку человека в боковой панели;
- искать корневого человека по имени или `Pxxx`-идентификатору;
- группировать таблицу по семьям и менять сортировку;
- работать на GitHub Pages через статический манифест `data/people/index.json`.

## Стек

- `HTML` + `CSS` + `JavaScript` без сборщика;
- `js-yaml` для чтения YAML в браузере;
- `vis-network` для визуализации графа;
- `Python` только для служебного генератора манифеста.

## Как устроены данные

Каждый человек хранится в отдельном файле `data/people/PXXX.yaml`, где `PXXX` это уникальный ID.

На практике сайт поддерживает много полей, включая:

- `birth_name`
- `name_changes`
- `birth`
- `death`
- `parents`
- `siblings`
- `spouses`
- `children`
- `education`
- `class_title`
- `religion`
- `nationality`
- `profession`
- `job_places`
- `military`
- `residences`
- `hobbies`
- `character`
- `appearance`
- `health`
- `other_info`
- `sources`
- `media`

## Как сайт загружает людей

GitHub Pages не умеет надёжно отдавать список файлов из директории `data/people/`, поэтому сайт не сканирует папку напрямую. Вместо этого он читает файл `data/people/index.json`, где перечислены все доступные `Pxxx`.

Это важный момент:

- при добавлении нового YAML нужно обновить `index.json`;
- если `index.json` устарел, часть людей не загрузится;
- локально есть fallback на чтение директории, но для деплоя нужно ориентироваться именно на манифест.

## Обновление данных

Когда добавляется, удаляется или переименовывается файл в `data/people/`, обнови манифест:

```powershell
python data\people\build_manifest.py
```

Скрипт пересоберёт `data/people/index.json` по текущим файлам `P*.yaml`.

Рекомендуемый порядок работы:

1. Добавить или изменить YAML-файлы в `data/people/`.
2. Запустить `python data\people\build_manifest.py`.
3. Проверить сайт локально.
4. Закоммитить изменения вместе с обновлённым `index.json`.
5. Задеплоить в GitHub Pages.

## Локальный запуск

Открывать `index.html` через `file://` не стоит: браузер блокирует `fetch` локальных файлов. Нужен обычный локальный HTTP-сервер.

Самый простой вариант:

```powershell
python -m http.server 8000
```

После этого открой:

```text
http://localhost:8000/
```

Также подойдут VS Code Live Server или любой другой статический сервер.

## Деплой на GitHub Pages

Проект подходит для публикации как обычный статический сайт:

- в репозиторий должны попасть `index.html`, `styles.css`, папка `js/` и папка `data/`;
- `data/people/index.json` должен быть актуальным;
- внешние библиотеки подключаются из CDN, поэтому отдельная сборка не нужна.

Если после деплоя граф и таблица пустые, в первую очередь проверь:

- существует ли `data/people/index.json` в опубликованной версии;
- перечислены ли в нём все нужные `Pxxx`;
- загружены ли сами `data/people/PXXX.yaml`.

## Что где отвечает

- `js/app.js` управляет интерфейсом, вкладками, выбором человека и инициализацией приложения.
- `js/data-loader.js` загружает манифест и YAML-файлы, а затем собирает dataset.
- `js/graph.js` строит визуальный граф родственных связей.
- `js/people-table.js` отвечает за табличное представление.
- `js/renderers.js` рендерит карточку человека.
- `js/person-name.js` формирует отображаемые имена.
- `js/family-groups.js` готовит группировку людей по семьям для таблицы.
